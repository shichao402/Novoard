# PRD-3: 通知与自动化规则

- 版本：v0.1
- 状态：Draft
- 契约引用：[contracts §6](../architecture/contracts.md)
- 相关 ADR：[0003](../adr/0003-hub-and-spoke-agent-egress.md)
- 载体：Novoard 仓（hub 侧通知扇出与规则引擎）

## 背景

远程触发的闭环缺最后一环：结果要主动找人，而不是人去查。同时事件驱动自动化（iOS 式"当 X 发生时做 Y"）是快捷中心概念的另一半，cronkit 只有 cron + manual 两类触发器，事件触发器需要 hub 侧的事件流水作底座。

## 目标用户

用户本人（通知接收者与规则定义者）。

## 用户故事

- US1：作为用户，任何 target 执行完成/失败，我想在企微/Bark 收到结果通知（含关键日志摘要），这样不用盯着面板。
- US2：作为用户，我想按 target 配置通知粒度（每次都通知 / 只失败才通知 / 不通知），这样高频低价值任务不刷屏。
- US3：作为用户，我想定义自动化规则"当事件 X 发生时，触发 target Y"，比如 webhook 收到某事件 → 自动跑一次巡检部署。
- US4：作为用户，Mac 离线但我触发远程任务时，我想收到明确的离线拒绝通知，而不是沉默。

## 功能需求

### F1 通知扇出

- 渠道：企微机器人消息（第一优先，内部可用性最高）、Bark（iOS 直达）。
- 触发点：task 终态（completed/failed）、审批门打开（input-required）、agent 离线任务被拒。
- 内容分级：摘要（target、终态、耗时）/ 详情（附关键日志尾部 N 行与实例 URL）。
- 频控：同 target 短窗口内重复通知合并（吸取 issue-handler digest 频控吞增量教训：事件只当触发器，通知按状态口径）。

### F2 通知配置

- 每 target 可配置通知策略字段（与 `audit` 平级）：`notify: always | on-failure | never`。
- 字段进契约 §1，定义时决定，运行时查表。

### F3 自动化规则（事件 → 动作）

- 规则形态：`when <event> then run <target> [on <agent>]`。
- 事件源（首批）：hub 收到的外部 webhook、task 终态事件、agent 上线/离线事件。
- 规则评估在 hub，动作走既有任务队列（不旁路），审计同车道。
- 规则定义 YAML 化，与 target 定义同风格的定义时判断（规则里显式写明事件匹配条件，运行时只做匹配）。

### F4 外部 webhook 入口

- hub 暴露带鉴权的通用 webhook 端点，事件入流水 → 规则引擎消费。
- 为 PRD-3 自身自动化与未来外部集成（仓库 push、监控告警）留公共底座。

## 非功能需求

- 通知失败不阻塞任务主流程（扇出异步化，失败进审计）。
- 规则引擎无定时能力（定时归 agent 本地 cron，ADR-0003 调度归属），事件匹配不含时间窗口语义。

## 验收标准

- AC1：远程触发部署，失败时 30s 内企微收到含失败原因摘要的通知。
- AC2：`notify: on-failure` 的 target 成功执行时不产生通知。
- AC3：配置"webhook 收到 X → 跑巡检 target"规则后，外部系统发 X，60s 内巡检自动执行并通知结果。

## 范围外

- AI 语义路由的通知（PRD-4）。
- 复杂编排（多步 DAG、条件分支流）——个人场景 YAGNI，n8n 式工作流不在本系统范围。
